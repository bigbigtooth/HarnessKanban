## 1 使用方式与公共契约

本计划按可独立验收的业务能力安排 38 项任务。先满足依赖和健康门禁，再确定实际文件所有者及任务边界；允许并行不表示自动派单。主线程维护公共契约、处理跨模块取舍，检查候选差异并完成最终集成验收。

任务中的源代码目录全部为**建议路径**，相对于工作区根目录；现在不表示存在相应文件。最终模块名、字段、服务签名和公共路由出口在 T01 冻结，实施者不得根据建议自行改变协议。任务的产品章节与 A 编号限定验收范围，D 编号指向实际 [DEVELOP.md](DEVELOP.md) 的同名章节。

所有命令均为**未来验收命令，当前不可执行**。标注 backend 的命令在未来 backend 工作目录与已准备环境执行；frontend 同理。命令选择器覆盖多个用例时，必须在报告中列出本任务实际运行的用例及数据断言，不能以零用例、全跳过或其他任务已通过代替本任务验收。

| 不可变公共契约 | 实施和验收要求 |
| --- | --- |
| 角色与项目授权 | 仅 SUPERVISOR/WORKER；员工不能发布/审核；授权即时生效，多主管/员工；最后有效主管不能撤销 |
| 任务状态与难度 | PREPARING、TODO、IN_PROGRESS、IN_REVIEW、DONE；难度 1–5 对应入门、简单、中等、困难、极难 |
| 等级选择 | 两种 Agent 都能选择任意等级；l1..l5 未传默认五级，部分出现仅值 1 包含，0 排除，非法/重复拒绝 |
| 两个任务接口 | GET /api/agent/v1/read_task/ 只读列表；POST /api/agent/v1/get_task/ 原子领一项，GET 领取为 405；AgentAPI 不保留旧列表/领取别名 |
| 空等级与容量 | 全 0 列表空；自动领取空回执，指定 task_id 等级不匹配 409；自动无候选优先于满容量，有候选才校验容量 |
| 固定执行时限 | L1 900、L2 1800、L3 7200、L4 28800、L5 86400 秒；从领取起固定，心跳/进度/上传/Key 重置/重放不延长，now>=deadline 拒绝新提交 |
| 领取与恢复 | 所有实例和 Web 代领共用数据库单例锁；单任务一有效执行；超时回待办，开放保留开放、指定保留指定；旧执行不能回写 |
| 审核和返工 | 仅有权且非提交者主管审核；Web 明确选择主管，记录未验证的代操作；驳回/重开回 TODO，保留历史并重新领取 |
| 请求来源 | WebAPI 本机无登录且具有本机管理信任边界；AgentAPI 以 AGENT_TOKEN 认证，不能由 body 指定他人身份 |
| 幂等与秘密 | 回执与业务同事务；返回前检查当前权限，重放先于新动作状态/时限；Key 明文不入回执/日志/Outbox/浏览器持久存储 |

D05、D07、D12、D13 中的事务适配属于实现细化：SQLite 读后写事务先首写保护行再读；领取先规划全部关联 ID，再分层锁全部项目/Agent/任务/执行，关系变化整笔重规划最多 3 次后 503；先建立执行再 CAS 填当前引用以满足即时外键。自动空 body 重放先内部读取历史元数据、验证当前读取权，再返回原执行，不能先选新候选。T04 提供不提交事务/不写业务审计的 finish_execution_locked（仅结束执行/释放槽）与 reset_in_progress_task_locked（清当前归属）；T08/T17/T20 的包装器分别负责 TODO 或 IN_REVIEW 及一次事件。T09 前置提供当前执行、Key 版本与固定截止的写 guard，T11/T16 复用，不构成前向依赖。这些选择不能被描述成新增用户需求。

执行时保护已有修改；不得吞异常、写死成功、用业务 Mock、删除测试或弱化断言。外部 PR、消息等副作用由执行端实现幂等；数据库结果防重不等于外部 exactly-once。

## 3 详细任务卡

### T01 冻结实施契约与领域服务边界

**状态：待开发。** **依赖：无。**

- **目标与参考：** 由主线程冻结请求、响应、操作上下文、领域服务输入输出与不变量，作为各模块接入依据。 对照：产品 1、2、6–8、11–14、20；A03、A09、A12、A14、A26、A27、A30；D01、D03、D05、D20、D21。
- **允许修改范围：** 建议：公共契约说明、backend/domain 的协议与枚举、两套 API 输入输出契约；由主线程独占公共文件。
- **设计思路：** 以产品文档 1.1 为唯一业务依据，列出 Web、Agent、system 三类操作来源与权限差异；实现者不得自行新增状态、续期端点或领取别名。
- **关键逻辑/算法：** 建立“动作→当前状态→权限→版本/执行检查→目标状态→原子副作用”矩阵；固定五级时长、l1..l5 解析和空领取优先级，并约定回执先于新动作资格校验。
- **验收准备：** 逐项准备产品 R01–R13、A01–A30 与接口字段对照；此任务先于代码，测试命令不适用。

**未来验收步骤/命令：**

1. 人工逐项核对五态、五难度及 900/1800/7200/28800/86400 秒，必须完全一致。
2. 人工走查自动领取、指定 task_id、全 0、重放、撤权、Web 代审核；每个分支有唯一结果且无跨模块待猜字段。
3. 主线程记录协议版本与批准的模块所有权；未冻结公共服务签名不得进入并行实现。

- **风险：** 公共协议漂移会使两套接口产生不同状态机；冲突必须由主线程裁决。
- **完成证据：** 契约对照表、动作矩阵、明确的服务协议版本和主线程审查记录。

### T02 建立可复现的本地运行与验收环境

**状态：待开发。** **依赖：T01。**

- **目标与参考：** 建立 frontend/backend 分离的 Vue 3、Django、FastAPI、Celery、Redis 工程与可重复测试入口。 对照：产品 10、17、18、21；A23、A24、A25；D02、D03、D19、D20。
- **允许修改范围：** 建议：frontend/package.json 与锁定文件、backend/pyproject.toml、backend/config、测试配置及 deploy 的开发环境配置；不实现业务动作。
- **设计思路：** 依赖版本由主线程在 D02 锁定；SQLite 使用统一绝对文件路径，MySQL 与真实 Redis 作为后续集成环境，业务测试不得自动退回 SQLite。
- **关键逻辑/算法：** 分开配置 Web、Agent、Worker、Beat 进程；环境缺失时明确失败或标注未执行，注册本计划列出的 pytest markers，并令 MySQL 用例校验实际连接类型。
- **验收准备：** 准备隔离的 SQLite、MySQL、Redis、私有文件目录和两个 API 进程；测试数据不得使用生产账户。

**未来验收步骤/命令：**

1. 未来在 backend 执行 `python -m pytest -m "unit and deployment"`：配置校验拒绝非法超时映射、不同 SQLite 路径与缺失必需项。
2. 未来按 D02 的已实现启动说明启动本地服务，确认 Web 仅绑定本机、两个 API 共用数据库、Worker/Beat 正确注册；这只验收工程基础。
3. 未来在 frontend 执行 `pnpm exec vitest run`：测试环境可收集并执行真实用例，不以零用例或全部跳过作为通过。

- **风险：** 未锁定依赖或假 MySQL 环境会使后续验收失真。
- **完成证据：** 依赖锁定文件、脱敏配置样例、实际启动记录及测试收集/执行结果。

### T03 建立业务模型、约束与单例锁迁移

**状态：待开发。** **依赖：T02。**

- **目标与参考：** 为身份、项目、文件、任务、执行、审核、活动、幂等及 Outbox 建立共享持久模型。 对照：产品 7.2、11；A06、A10、A23、A29；D04、D05。
- **允许修改范围：** 建议：backend/apps 的模型与迁移、对应模型验收；模型和迁移由单一所有者维护。
- **设计思路：** 仅使用 Django 迁移；关键关系用普通外键、唯一性及领域事务表达，不依赖 SQLite 专有约束。历史实体归档或禁用，禁止级联删除执行证据。
- **关键逻辑/算法：** 数据迁移建立 TaskClaimLock 固定 id=1；约束难度 1–5、执行序号唯一、每执行仅一正式提交、每提交仅一审核、成员组合及幂等作用域唯一。
- **验收准备：** 准备全新 SQLite/MySQL 数据库，以及含执行、结果和附件引用的历史数据集。

**未来验收步骤/命令：**

1. 未来在 backend 执行 `python -m pytest -m "unit and workflow"`：无效难度、重复提交/审核、非法关系被拒绝，历史外键不能被级联删除。
2. 未来在 backend 执行 `python -m pytest -m "mysql and deployment"`：空库迁移与重复部署均保留唯一 id=1 锁行；两套 API 识别同一模型版本。
3. 人工检查迁移差异和索引，确认没有独立 FastAPI 迁移体系及明文 Key 字段。

- **风险：** 丢失锁行或不可移植约束会破坏领取正确性；不得运行时静默补成无锁模式。
- **完成证据：** 迁移清单、两种数据库的约束结果、锁行与历史引用检查记录。

### T04 实现共享事务、数据库时钟与连接生命周期

**状态：待开发。** **依赖：T03。**

- **目标与参考：** 提供共享事务、数据库时钟、连接生命周期及执行结束/归属清理原语，供后续包装器复用。 对照：产品 7、10.2、11、12、17.3；A10、A13、A17、A18、A23、A30；D03、D05、D10、D13。
- **允许修改范围：** 建议：backend/domain 的事务/时钟/锁基础、finish_execution_locked 与 reset_in_progress_task_locked、AgentAPI 同步调用桥；公共基础由唯一所有者维护。
- **设计思路：** 最外层服务负责事务与业务结果；底层原语不另开或提交事务、不写业务审计或 Outbox。finish_execution_locked 不改变任务状态；reset_in_progress_task_locked 专用于进行中转待办。连接、鉴权和 ORM 在同一同步线程使用并 finally 清理。
- **关键逻辑/算法：** MySQL 规划 ID 后分层锁全部项目/Agent/任务/执行，SQLite 任何业务 SELECT 前首写固定保护行；关系变化整笔重规划最多 3 次后 503。锁后读取新 UTC 时间。finish_execution_locked 条件改 ended_at/原因并减一次槽，异常槽整笔失败；reset_in_progress_task_locked 以当前执行和版本 CAS 同时写 TODO、清归属/引用/本轮字段并将任务版本加一，匹配行数必须为一。包装器只写一次事件/回执，不重复改状态或加版本。
- **验收准备：** 用 T03 的真实数据库模型准备当前执行、已结束执行、正常/异常槽及两个连接的锁等待；此阶段不要求尚未实现的 submit 端点。

**未来验收步骤/命令：**

1. 未来在 backend 执行 `python -m pytest -m "unit and workflow"`：finish 原语只结束/减槽而不改任务，reset 原语同一 CAS 转 TODO、清字段且只加一次版本；二者均不提交事务或写审计/Outbox，失败全回滚，重复不重复扣槽。
2. 未来在 backend 执行 `python -m pytest -m "mysql and concurrency and timeout"`：两个真实结束原语调用仅一次生效，锁等待后使用新数据库时间；不通过调用未来 submit 端点验收。
3. 未来在 backend 执行 `python -m pytest -m "fault and api"`：调用者事务回滚后原语变更全撤销，SQLite 首写后读，异常/请求结束均清理工作线程连接。

- **风险：** 旧时间、跨线程连接、反向补锁和提前提交会绕过固定时限或破坏全局锁；这些是 D05 实现细化，不是新增产品需求。
- **完成证据：** 真实原语锁竞争、时钟时间线、调用者回滚结果、无额外事件/事务提交及连接检查。

### T05 建立两套 API 的协议和请求边界

**状态：待开发。** **依赖：T01、T02、T04。**

- **目标与参考：** 交付统一请求/响应、Host/Origin/内容类型边界、头字段解析和最小探针，后续业务端点按冻结协议接入。 对照：产品 2.4、12–14、17；A02、A23、A24、A27；D03、D06。
- **允许修改范围：** 建议：backend/webapi、backend/agentapi 的应用/协议基础与接口测试；路由注册公共文件由单一所有者集成。
- **设计思路：** 适配层负责格式与操作来源，不实现业务权限或状态机。先验协议/边界与最小 live，完整 Agent 鉴权在 T07/T09，GET get_task 与真实领取路由在 T18。
- **关键逻辑/算法：** 统一框架校验/业务错误响应，定义 400/401/403/404/409/503 映射；AGENT_TOKEN 保留下划线，Web 校验 Host/Origin/JSON及受控 multipart；live 无敏感详情。业务路由注册只能按 T01 合同，不能建立额外别名。
